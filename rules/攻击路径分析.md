# 攻击路径分析

## 概述

攻击路径分析（Attack Path Analysis）是 TARA 分析的第四步，在威胁场景识别完成后，从攻击者视角构建实现威胁的具体攻击路径，并对每个攻击路径进行可行性评分和风险等级判定。

本规范基于 ISO/SAE 21434 标准，定义攻击路径的编号规则、攻击可行性评分体系（ET/EXP/KN/WO/EQ）、安全风险等级矩阵（IL × AL → SL）和攻击路径描述编写规范。

---

## 一、攻击路径 ID

攻击路径 ID 命名规则：

```
AP_<三位序号>
```

**格式说明：**

| 组成部分 | 含义 | 规则 |
|---------|------|------|
| `AP` | Attack Path | 攻击路径前缀 |
| `AS_<类型缩写>` | 引用资产 ID 的类型前缀 | 与关联资产的类型保持一致：`Da`/`Hw`/`Sw`/`Ee`/`Dt` |
| `_<三位序号>` | 从 001 开始递增 | 按 STRIDE 顺序排列，同一资产下有多个威胁时独立编号 |

**示例：**
- `AP_AS_Da_001` — 第一个攻击路径
- `AP_AS_Da_002` — 第二个攻击路径

## 二、攻击路径描述编写规范

### 编写公式

攻击路径描述遵循"入口 → 步骤 → 影响"的三段式结构：

> **[攻击入口点]**→**[攻击步骤 1：如何获得相关信息]**→**[攻击步骤 2：如何进入系统]** → **[攻击步骤 3：如何在系统内横向移动]** → **[攻击步骤 4：如何实现威胁目标]** → **[造成的损害后果]**

### 编写要点

1. **明确攻击入口**：从系统边界出发，说明攻击者从哪个接口/信道进入（无线、OBD、USB、APP 等）
2. **获取到的信息**：在攻击之前，攻击者需要获取到什么样的信息或者分析得到什么内容（报文，传输协议，流量等）
3. **步骤递进**：每一步是前一步的必然延续，形成完整攻击链（Kill Chain）
4. **技术可行**：每一步描述应包含具体的技术手段（嗅探、重放、注入、逆向、暴力破解等）
5. **明确所需能力**：汇总攻击者完成全部步骤所需的综合能力（技能、工具、时间）
6. **关联威胁**：攻击路径应明确关联到具体的威胁场景 ID

### 标准示例

#### 远程攻击路径示例

```
[入口] 攻击者通过公网对 TSP 平台发起 API 接口扫描，发现存在未鉴权的车辆查询接口。
→ [步骤1] 利用接口缺陷枚举获取目标车辆 VIN 与 TBOX 标识，构造合法远程控制请求格式。
→ [步骤2] 通过重放攻击向 TSP 平台批量下发伪造的远程解锁指令，绕过指令频率限制。
→ [步骤3] TSP 平台将伪造指令下发至目标车辆 TBOX，TBOX 转发至 BCM 执行车门解锁。
→ [后果] 攻击者可在车主不知情的情况下非法开启车门，窃取车内财物。
→ 关联威胁: CsTS_AS_Da_001（Spoofing）、CsTS_AS_Da_002（Tampering）
```

#### 物理接入攻击路径示例

```
[入口] 攻击者通过物理接触接入车辆 OBD II 诊断接口。
→ [步骤1] 使用 CAN 总线分析工具（如 PCAN、CANoe）连接 OBD 接口，监听整车 CAN 通信。
→ [步骤2] 通过逆向分析 CAN 报文，识别 VCU→MCU 的扭矩控制报文 ID 与数据场格式。
→ [步骤3] 向 CAN 总线注入伪造的扭矩控制报文，覆盖 VCU 正常下发的扭矩指令。
→ [后果] 攻击者可通过注入恶意扭矩值控制车辆加减速行为，威胁行车安全。
→ 关联威胁: CsTS_AS_Da_003（Tampering）
```

#### 无线近场攻击路径示例

```
[入口] 攻击者在车辆附近（<50m）部署软件定义无线电（SDR）设备。
→ [步骤1] 通过 SDR 扫描并锁定 PEPS 钥匙与车辆之间的无线通信频段（125kHz/433MHz）。
→ [步骤2] 录制车主锁车/解锁时的无线信号，分析通信协议与滚动码机制。
→ [步骤3] 利用中继攻击设备将钥匙信号从车主位置中继到车辆旁，欺骗车辆以为钥匙在附近。
→ [后果] 攻击者可绕过 PEPS 认证，实现无钥匙进入和车辆启动。
→ 关联威胁: CsTS_AS_Ee_001（Spoofing）
```

## 三、攻击可行性评分体系

攻击可行性从以下五个维度进行评分，每个维度按攻击难度从低到高赋予分值：

### 评分维度

| 维度 | 英文 | 缩写 | 含义 |
|------|------|------|------|
| 经过时间 | Elapsed Time | ET | 攻击者识别并利用漏洞所需的总耗时 |
| 专业经验 | Expertise | EXP | 攻击者需要具备的技术技能水平 |
| 目标知识度 | Knowledge of Target | KN | 攻击者需要对目标系统的了解程度 |
| 机会窗口 | Window of Opportunity | WO | 实施攻击所需的时间窗口/访问机会 |
| 设备 | Equipment | EQ | 攻击所需的硬件/软件工具 |

### 各维度评分标准

#### ET — 经过时间（Elapsed Time）

| 分值 | 等级 | 判定标准 |
|------|------|---------|
| **0** | ≤1 天 | 攻击可在一天内识别并完成利用 |
| **1** | ≤1 周 | 攻击可在一周内识别并完成利用 |
| **2** | ≤1 月 | 攻击可在一个月内识别并完成利用 |
| **3** | ≤3 月 | 攻击可在三个月内识别并完成利用 |
| **4** | ≤6 月 | 攻击可在六个月内识别并完成利用 |
| **7** | >6 月 | 攻击需要六个月以上时间识别并完成利用 |

#### EXP — 专业经验（Expertise）

| 分值 | 等级 | 判定标准 |
|------|------|---------|
| **0** | 外行 Layman | 无特殊技能要求，普通人即可完成 |
| **1** | 熟练者 Proficient | 具备基本的汽车电子/网络知识 |
| **2** | 专家 Expert | 具备深入的汽车网络安全专业知识 |
| **3** | 多领域专家 Multiple Expert | 需要跨多个专业领域的综合知识 |
| **4** | 顶尖研究者 Elite Researcher | 需要行业顶尖水平的原创性研究 |

#### KN — 目标知识度（Knowledge of Target）

| 分值 | 等级 | 判定标准 |
|------|------|---------|
| **0** | 公开信息 Public | 目标系统的信息已公开或可从公开渠道获取 |
| **1** | 受限信息 Restricted | 需要获取受控分发/保密的系统信息 |
| **2** | 敏感信息 Sensitive | 需要获取内部设计文档、通信矩阵等敏感资料 |
| **3** | 关键信息 Critical | 需要获取加密密钥、安全策略等核心涉密信息 |

#### WO — 机会窗口（Window of Opportunity）

| 分值 | 等级 | 判定标准 |
|------|------|---------|
| **0** | 无限 Unlimited | 攻击可随时进行，无时间或访问限制 |
| **1** | 容易 Easy | 攻击窗口较容易获得（如车辆长期停放） |
| **2** | 中等 Moderate | 攻击窗口需要一定条件（如特定时间段） |
| **3** | 困难 Difficult | 攻击窗口难以获得（如需要特定车辆状态） |
| **4** | 无 None | 几乎无法获得攻击窗口 |

#### EQ — 设备（Equipment）

| 分值 | 等级 | 判定标准 |
|------|------|---------|
| **0** | 无设备 | 不使用任何设备即可完成攻击 |
| **1** | 标准设备 Standard | 使用普通消费级设备即可 |
| **2** | 专业设备 Specialized | 需要专业级设备（如 CAN 分析仪、SDR） |
| **3** | 定制设备 Bespoke | 需要定制开发专用攻击设备 |
| **4** | 多设备组合 Multiple Bespoke | 需要多种定制设备的组合协同 |

### 总分计算

```
TOTAL = ET + EXP + KN + WO + EQ
```

### 攻击可行性等级（AL）映射

| TOTAL 范围 | 攻击可行性等级 AL | 英文 | 含义 |
|-----------|-----------------|------|------|
| TOTAL ≥ 25 | **非常低 Very Low** | Very Low | 攻击几乎不可行，所需条件极其苛刻 |
| 20 ≤ TOTAL ≤ 24 | **低 Low** | Low | 攻击可行性低，需要较强的综合能力 |
| 14 ≤ TOTAL ≤ 19 | **中等 Medium** | Medium | 攻击有一定可行性，专业技术团队可实现 |
| 0 ≤ TOTAL ≤ 13 | **高 High** | High | 攻击可行性高，个人或小团队即可实现 |

## 四、安全风险等级矩阵

### 影响等级 IL（Impact Level）

影响等级从损害场景的影响分析继承而来（参见 [影响分析](./影响分析.md)）：

| IL | 影响等级 | 英文 | 对应 Total 范围 |
|----|---------|------|----------------|
| 1 | 轻微 | Minor / Negligible | Total ≤ 20 |
| 2 | 中等 | Moderate | 20 < Total ≤ 100 |
| 3 | 主要 | Major | 100 < Total ≤ 1000 |
| 4 | 严重 | Severe | Total > 1000 |

### 安全风险等级矩阵（IL × AL → SL）

根据 ISO/SAE 21434，安全风险等级 SL 由影响等级 IL 和攻击可行性等级 AL 交叉确定：

```
                    攻击可行性 AL
                ┌──────┬──────┬──────┬──────┐
                │  1   │  2   │  3   │  4   │
                │非常低│ 低   │ 中等  │ 高   │
        ┌───────┼──────┼──────┼──────┼──────┤
    IL  │1 轻微 │ SL1  │ SL1  │ SL1  │ SL1  │
        │2 中等 │ SL1  │ SL2  │ SL2  │ SL3  │
        │3 主要 │ SL1  │ SL2  │ SL3  │ SL4  │
        │4 严重 │ SL2  │ SL3  │ SL4  │ SL5  │
        └───────┴──────┴──────┴──────┴──────┘
```

### 安全风险等级 SL 含义

| SL | 等级 | 英文 | 含义 |
|----|------|------|------|
| **1** | 非常低 | Very Low | 发生造成的影响几乎不存在 |
| **2** | 低 | Low | 风险低，导致资产受到影响的可能性较小 |
| **3** | 中 | Medium | 风险中，导致资产受到影响的可能性较大 |
| **4** | 高 | High | 风险高，可能导致业务系统异常运行，造成经济损失 |
| **5** | 严重 | Severe | 风险严重，可能严重影响业务系统运行，造成重大损失 |

### 计算示例

| 示例 | IL | AL | 计算 | SL | 含义 |
|------|----|----|------|----|------|
| 例1 | 1 (轻微) | 高 (4) | 轻微影响 × 高可行性 | SL1 | 影响极小，即使容易攻击也无实质风险 |
| 例2 | 2 (中等) | 中等 (3) | 中等影响 × 中等可行性 | SL2 | 有一定影响和可行性，风险低但需要关注 |
| 例3 | 3 (主要) | 高 (4) | 主要影响 × 高可行性 | SL4 | 影响大且容易攻击，必须缓解 |
| 例4 | 3 (主要) | 非常低 (1) | 主要影响 × 极低可行性 | SL1 | 影响大但几乎不可能攻击，可保留风险 |
| 例5 | 4 (严重) | 高 (4) | 严重影响 × 高可行性 | SL5 | 最严重组合，必须消除风险 |

## 五、攻击路径分析填写规范

### 完整字段

| 字段 | 说明 | 示例 |
|------|------|------|
| 资产 Asset | 资产 ID + 名称 | `AS_Da_001 远程启动/关闭信号` |
| 损害场景 ID | 关联的 CsDS | `CsDS_AS_Da_001` |
| 威胁场景 ID | 关联的 CsTS | `CsTS_AS_Da_001` |
| 攻击路径描述 | 入口→步骤→后果 完整描述 | 见上节标准示例 |
| 攻击可行性评分 | ET/EXP/KN/WO/EQ 五项分值 | 见上节评分标准 |
| 攻击可行性等级 AL | TOTAL → AL 映射 | `高 High (AL=4)` |
| 影响等级 IL | 从损害场景继承 | `IL3：Major/M1（主要）` |
| 安全风险等级 SL | IL × AL 矩阵查表 | `SL4 高 High` |

### 评分理由编写规范

每个 ET/EXP/KN/WO/EQ 维度的评分必须附带理由，格式如下：

```
ET=X：理由应具体说明攻击所需的时间范围和依据。
   示例: "需要约 2 周时间进行 CAN 总线逆向分析与报文测试，符合 ≤1 月标准"
EXP=X：理由应说明攻击者需要具备哪些具体技能。
   示例: "需要具备 CAN 协议分析能力和汽车电子基础知识，属于熟练者级别"
KN=X：理由应说明攻击者需要获得哪些关于目标的具体信息。
   示例: "CAN 通信矩阵属于内部文档，需要从内部渠道获取，属于受限信息"
WO=X：理由应说明攻击机会的获取条件和频率。
   示例: "OBD 接口物理接触需要车辆无人值守时段，机会窗口较容易获得"
EQ=X：理由应列举攻击所需的具体设备和工具。
   示例: "需要 PCAN-USB 接口和 CANoe/PCAN-View 软件，属于标准设备即可"
```

## 六、填写完成检查清单

- [ ] 攻击路径 ID 符合 `AP-XXX` 格式
- [ ] 每个威胁场景至少关联了 1 条攻击路径
- [ ] 攻击路径描述包含完整的入口→步骤→后果链条
- [ ] AL 的五个维度（ET/EXP/KN/WO/EQ）都有分值且附带评分理由
- [ ] ET/EXP/KN/WO/EQ 的分值在各自允许范围内
- [ ] TOTAL = ET+EXP+KN+WO+EQ 计算正确
- [ ] AL 等级根据 TOTAL 正确映射
- [ ] IL 从损害场景正确继承
- [ ] SL 根据 IL×AL 矩阵正确查表
- [ ] 关联的损害场景 ID 和威胁场景 ID 填写正确
