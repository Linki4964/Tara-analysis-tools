# 风险处置与安全声明

## 概述

风险处置与安全声明（Risk Treatment and Safety Statement）是 TARA 分析的第五步和最后一步，基于攻击路径分析的安全风险等级（SL），确定风险处置策略，并制定网络安全目标、需求和声明。

本规范基于 ISO/SAE 21434 标准，定义风险处置决策规则、网络安全目标（Cybersecurity Goal）编号与编写规范、网络安全声明（Cybersecurity Claim）的编号与编写规范。

---

## 一、风险处置决策规则

### 处置决策与 SL 映射

根据安全风险等级 SL 确定处置决策：

| SL | 处置决策 | 英文 | 说明 |
|----|---------|------|------|
| **5** | **消除 Eliminate** | Eliminate | 移除风险源，规避风险。必须采取设计变更从根本上消除风险来源。 |
| **4** | **缓解 Mitigate** | Mitigate | 缓解风险，降低风险。通过安全控制措施将风险降低到可接受水平。 |
| **3** | **转移 Share** | Share | 共享或转移风险。通过合同协议、保险、供应商责任等方式转移风险。 |
| **2** | **保留 Accept** | Accept / Retain | 接受或保留风险。风险处于可接受水平，无需额外控制措施。 |
| **1** | **保留 Accept** | Accept / Retain | 接受或保留风险。风险极低，无需额外控制措施。 |

### 处置决策详细说明

#### 消除（Eliminate）— SL=5
- **适用场景**：风险严重，安全风险等级最高，可能导致严重人身伤害或重大财产损失
- **典型措施**：移除受影响的功能、更换不安全的通信协议、物理隔离高危接口
- **示例**：取消远程启动功能中未经加密的指令通道，重新设计为端到端加密架构

#### 缓解（Mitigate）— SL=4
- **适用场景**：风险高，可能造成较大影响且攻击可行性较高
- **典型措施**：增加加密传输、身份认证、访问控制、安全监控、入侵检测等
- **示例**：对远程控制指令增加 TLS 1.3 加密传输 + HMAC 签名校验 + 指令频率限制

#### 转移（Share）— SL=3
- **适用场景**：风险中等，可通过外部机制分担
- **典型措施**：供应商安全责任合同、网络安全保险、外包安全运维
- **示例**：要求 TSP 平台供应商承担云端安全防护责任，签订 SLA 安全服务水平协议

#### 保留（Accept / Retain）— SL=1,2
- **适用场景**：风险低或极低，攻击可行性非常低或影响极小
- **典型措施**：记录风险登记册、定期回顾、保持现状
- **示例**：对于需要物理拆卸车辆内饰才能接触到内部 CAN 线路的攻击路径，保留风险并记录

### 风险处置决策输出格式

| 字段 | 说明 | 示例 |
|------|------|------|
| 损害场景 ID | 关联的 CsDS | `CsDS_AS_Da_001` |
| 威胁场景 ID | 关联的 CsTS | `CsTS_AS_Da_001` |
| 影响等级 IL | 从损害影响分析继承 | `IL3：Major/M1（主要）` |
| 攻击可行性等级 AL | 从攻击路径分析继承 | `高 High` |
| 风险评级 SL | IL × AL 矩阵结果 | `4` |
| 处置决策 | SL 对应的处置决策 | `缓解 Mitigation` |

## 二、网络安全目标（Cybersecurity Goal）

### 目标 ID

网络安全目标 ID 命名规则：

```
CsGO_<相关项缩写>_<三位序号>
```

**格式说明：**
- `CsGO` = Cyber Security Goal（网络安全目标前缀）
- `_<相关项缩写>` = 相关项（Item）缩写，如 `VIU`
- `_<三位序号>` = 从 001 开始递增，全局编号

**示例：**
- `CsGO_VIU_001` — VIU 相关项的第 1 个网络安全目标
- `CsGO_VIU_002` — VIU 相关项的第 2 个网络安全目标

### 目标编写规范

#### 编写公式

网络安全目标描述了"需要保护什么"以及"如何保护"，是对风险处置措施的高度概括：

> **[需要保护的安全属性/功能] + [应采用的保护措施/技术手段] + [防止的安全威胁]**

#### 编写要点

1. **目标可合并**：多个相关的损害场景/威胁场景可以共用一个网络安全目标（当它们的保护措施相同时）
2. **描述技术手段**：明确采用什么技术/机制来保护（加密、认证、隔离、校验等）
3. **明确防护对象**：清楚说明保护的是什么资产或功能
4. **目标可度量**：目标应该是可验证的（能够通过测试确认是否达成）

#### 标准示例

| 合并场景 | 网络安全目标 ID | 网络安全目标 |
|---------|---------------|-------------|
| 多项远程控制信号的安全性 | CsGO_VIU_001 | 远程控制信号（启动/闭锁/空调）需采用加密传输，防止中间人攻击和篡改 |
| CAN 总线访问控制 | CsGO_VIU_008 | CAN 总线应限制非授权访问，实施通信矩阵管控，禁止非法节点接入与报文注入 |
| GW 网关网段隔离 | CsGO_VIU_009 | 网关内部应实现网段隔离，防止跨网段非法访问与攻击横向扩散 |
| 固件安全升级 | CsGO_VIU_010 | 在线升级应保证升级包的真实性，进行数字签名校验，防止固件篡改与恶意植入 |
| 安全启动密钥保护 | CsGO_VIU_011 | 安全启动密钥应在安全存储区域加密保存，防止未授权读取与复制 |
| 敏感数据保护 | CsGO_VIU_012 | 敏感数据（VIN、身份认证信息、故障日志）应加密存储与传输，防止泄露与篡改 |
| 外部接口防护 | CsGO_VIU_013 | 禁用所有不必要的硬件外部接口（JTAG、UART、USB 等），保护系统和内存中的数据 |
| 用户权限管控 | CsGO_VIU_014 | 应对用户权限实施最小权限分配原则，禁止越权访问系统功能与数据 |
| 安全事件日志 | CsGO_VIU_015 | 应对远程连接指令进行安全日志记录，记录安全事件用于追溯与审计 |
| 射频信号保护 | CsGO_VIU_016 | 射频信号（PEPS 钥匙通信）应采用滚动码与加密机制，防止重放与中继攻击 |
| USB 接口管控 | CsGO_VIU_017 | USB 接口设备应进行访问控制或者其他保护，禁止外部设备中的恶意文件进入系统 |
| 关键控制器安全 | CsGO_VIU_018 | 应对关键控制器集成安全模块（HSM），保护数据不被破坏或篡改 |

### 不需要设定目标的情况

当处置决策为"保留 Retain"时，对应的威胁场景**不需要设定网络安全目标**。此时各字段填写 `/`：

```
损害场景: CsDS_AS_Da_003
安全风险等级 SL: 1
处置决策: 保留 Retaining the risk
网络安全目标 ID: /
网络安全目标: /
```

## 三、网络安全需求（Cybersecurity Requirement）

网络安全需求是网络安全目标的**技术实现规格**，描述具体的技术实现要求。

### 编写格式

> **[具体技术措施] + [覆盖范围] + [验证方式]**

### 示例

对应 `CsGO_VIU_001`（远程控制信号加密传输）：

> 1. TBOX 与 TSP 之间所有远程控制指令通信必须采用 TLS 1.3 加密传输，证书链需通过 PKI 体系验证。
> 2. TBOX 接收到远程指令后需校验 HMAC-SHA256 签名，签名密钥存储于 TBOX 安全存储区域。
> 3. 单用户每分钟最多下发 10 条远程控制指令，超出频率限制自动拒绝并记录安全日志。

## 四、网络安全声明（Cybersecurity Claim）

### 声明 ID

网络安全声明 ID 命名规则：

```
CsCL_<相关项缩写>_<三位序号>
```

**格式说明：**
- `CsCL` = Cyber Security Claim（网络安全声明前缀）
- `_<相关项缩写>` = 相关项（Item）缩写，如 `VIU`
- `_<三位序号>` = 从 001 开始递增，全局编号

### 声明编写规范

#### 编写公式

网络安全声明是将网络安全目标/需求转化为**可测试、可验证**的陈述句，用于确认安全措施已正确实施：

> **[验证对象] + [满足的安全要求] + [验证方式/证据]**

#### 编写要点

1. **声明 = 目标的可测试版本**：每个网络安全目标可以对应多个声明，每个声明描述一个可独立验证的安全断言
2. **明确验证方式**：测试、检查、审查、渗透测试等
3. **可执行性**：声明应足够具体，使测试工程师可以据此编写测试用例

#### 标准示例

| 关联目标 | 网络安全声明 ID | 网络安全声明 |
|---------|---------------|-------------|
| CsGO_VIU_001 | CsCL_VIU_001 | 经验证，TBOX 与 TSP 之间的远程控制指令通信链路已启用 TLS 1.3 加密，通过抓包分析确认无明文指令传输。 |
| CsGO_VIU_001 | CsCL_VIU_002 | 经验证，非法签名的远程控制指令被 TBOX 拒绝执行，TBOX 安全日志记录了签名校验失败事件。 |
| CsGO_VIU_008 | CsCL_VIU_003 | 经验证，GW 网关的 CAN 报文过滤规则表已正确配置，未授权的报文 ID 在物理层被拦截，未转发至车内 CAN 网络。 |
| CsGO_VIU_010 | CsCL_VIU_004 | 经验证，OTA 升级包在刷写前通过 RSA-2048 签名校验，未经签名的固件包被拒绝刷写并上报告警。 |

## 五、风险处置与安全声明填写模板

### 完整字段一览

| 字段 | 说明 | 示例 |
|------|------|------|
| 损害场景 ID | CsDS 编号 | `CsDS_AS_Da_001` |
| 威胁场景 ID | CsTS 编号 | `CsTS_AS_Da_001` |
| 影响等级 IL | 从损害影响分析继承 | `IL3：Major/M1（主要）` |
| 攻击可行性等级 AL | 从攻击路径分析继承 | `高 High` |
| 风险评级 SL | IL × AL 矩阵结果 | `4` |
| 处置决策 | Eliminate/Mitigate/Share/Accept | `缓解 Mitigation` |
| 网络安全目标 ID | CsGO 编号 | `CsGO_VIU_001` |
| 网络安全目标 | 目标描述 | `远程控制信号需采用加密传输...` |
| 网络安全需求 | 技术实现要求 | `TLS 1.3 + HMAC-SHA256 签名...` |
| 网络安全声明 ID | CsCL 编号 | `CsCL_VIU_001` |
| 网络安全声明 | 可验证声明 | `经验证，TBOX-TSP 通信已启用 TLS 1.3...` |

### 处置决策为"保留"时的填写规则

当处置决策为"保留（Retain/Accept）"时，网络安全目标/需求/声明**不需要填写**：

```
损害场景 ID: CsDS_AS_Da_003
影响等级 IL: IL3：Major/M1（主要）
攻击可行性等级 AL: 非常低 Very Low
风险评级 SL: 1
处置决策: 保留 Retaining the risk
网络安全目标 ID: /
网络安全目标: /
网络安全需求: /
网络安全声明 ID: /
网络安全声明: /
```

> **为什么影响等级高但最终保留风险？**
> 因为攻击可行性为"非常低"（TOTAL ≥ 25），IL=3 × AL=1 → SL=1。虽然影响可能很大，但攻击几乎不可能实现，所以整体风险等级为最低。这是 ISO/SAE 21434 风险矩阵的核心逻辑：**风险 = 影响 × 可行性**。

## 六、TARA 分析全流程 ID 追溯链

```
步骤1: 网络安全相关项定义
  └── 资产 AS_Da_001

步骤2: 影响分析
  └── 损害场景 CsDS_AS_Da_001（保密性）
  └── 损害场景 CsDS_AS_Da_002（完整性）

步骤3: 威胁分析
  └── 威胁场景 CsTS_AS_Da_001（Information Disclosure → CsDS_AS_Da_001）
  └── 威胁场景 CsTS_AS_Da_002（Tampering → CsDS_AS_Da_002）

步骤4: 攻击路径分析
  └── 攻击路径 AP-001 → IL3 × AL4 → SL4

步骤5: 风险处置与安全声明
  └── 处置决策: 缓解 Mitigation
  └── 网络安全目标: CsGO_VIU_001
  └── 网络安全声明: CsCL_VIU_001
```

### ID 命名总览

| 步骤 | ID 前缀 | 格式 | 示例 |
|------|---------|------|------|
| 资产 | `AS_` | `AS_<类型>_<序号>` | `AS_Da_001` |
| 损害场景 | `CsDS_AS_` | `CsDS_AS_<类型>_<序号>` | `CsDS_AS_Da_001` |
| 威胁场景 | `CsTS_AS_` | `CsTS_AS_<类型>_<序号>` | `CsTS_AS_Da_001` |
| 攻击路径 | `AP-` | `AP-<序号>` | `AP-001` |
| 网络安全目标 | `CsGO_` | `CsGO_<相关项>_<序号>` | `CsGO_VIU_001` |
| 网络安全声明 | `CsCL_` | `CsCL_<相关项>_<序号>` | `CsCL_VIU_001` |

## 七、填写完成检查清单

- [ ] 损害场景 ID 和威胁场景 ID 正确关联
- [ ] IL 从损害影响分析正确继承
- [ ] AL 从攻击路径分析正确继承
- [ ] SL 根据 IL × AL 矩阵正确查表
- [ ] 处置决策符合 SL 映射规则
- [ ] SL=5 → Eliminate（消除）
- [ ] SL=4 → Mitigate（缓解）
- [ ] SL=3 → Share（转移）
- [ ] SL=1,2 → Accept/Retain（保留）
- [ ] SL=1,2 时，网络安全目标/声明填写 `/`
- [ ] 网络安全目标描述了具体的技术防护手段
- [ ] 网络安全目标可被多个相关威胁场景合并共用
- [ ] 网络安全声明是可测试/可验证的
- [ ] 所有 ID 符合命名规范且全局唯一
