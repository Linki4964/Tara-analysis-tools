# 影响分析部分

## 填写规范

### 资产 Asset
资产 ID + Name，格式为 `AS_<类型缩写>_<序号> <资产名称>`。

**示例：**
- `AS_Da_001 远程启动 / 关闭信号（APP/TSP→TBOX→VCU）`
- `AS_Da_004 远程闭锁 / 解锁信号（APP/TSP→TBOX→BCM）`
- `AS_Hw_001 OBD 诊断接口`

### 资产类型
按照 `网络安全相关项描述` 中定义的分类标准进行编写，分为以下五大类。
详细分类判定规则、边界案例和决策树请参考 [网络安全相关项描述](./网络安全相关项描述.md)。

| 类型 | 英文 | 编号前缀 | 存在形式 | 典型示例 |
|------|------|---------|---------|---------|
| 数据流 | Data Flow | `AS_Da_` | 动态传输中的信号/指令/报文 | 远程启动信号（APP→TBOX→VCU） |
| 硬件 | Hardware | `AS_Hw_` | 物理设备/芯片/ECU/总线 | VCU、BCM、整车 CAN 总线 |
| 软件 | Software | `AS_Sw_` | 代码程序/固件包/OS/协议栈 | MCU 固件包、CAN 通信协议栈 |
| 外部实体 | External Entity | `AS_Ee_` | 系统边界外交互终端/平台 | TSP 平台、APP、外部诊断设备 |
| 数据 | Data Asset | `AS_Dt_` | 静态存储的信息/密钥/日志 | 安全启动密钥、VIN、故障日志 |

### 资产安全属性
需要在以下三个选项中填写其中一项（每个资产按安全属性拆分为多行，每行针对一个属性编写损害场景）：

- **保密性 Confidentiality**：资产内容被未授权方获取/泄露导致的损害
- **完整性 Integrity**：资产内容被未授权篡改/伪造导致的损害
- **可用性 Availability**：资产不可用/无法访问导致的损害

> 注意：每个资产 × 每个受影响的安全属性 = 一组损害场景。例如一个数据流资产涉及保密性和完整性两个属性，则需要分别编写两组损害场景。

### 损害场景ID
损害场景 ID 命名规则：

```
CsDS_AS_<资产类型缩写>_<三位序号>
```

**格式说明：**
- `CsDS` = Cyber Security Damage Scenario（损害场景前缀）
- `AS_<类型缩写>` = 引用资产 ID 中的类型前缀，如 `Da`（Data Flow）、`Hw`（Hardware）、`Sw`（Software）等
- `_<三位序号>` = 从 001 开始递增的序号，同一资产下按保密性→完整性→可用性顺序编号

**示例：**
- `CsDS_AS_Da_001` — 资产 AS_Da_001 保密性相关损害场景
- `CsDS_AS_Da_002` — 资产 AS_Da_001 保密性相关损害场景（第2个）
- `CsDS_AS_Da_003` — 资产 AS_Da_001 完整性相关损害场景

## 损害场景描述编写规范

### 编写公式

损害场景描述遵循以下三要素公式：

> **[资产名称]的[安全属性]遭到破坏，[攻击行为/破坏方式]，[对车辆/用户/组织的具体影响后果]。**

### 三要素说明

| 要素 | 说明 | 示例 |
|------|------|------|
| **资产 + 安全属性** | 明确指出哪个资产的哪个安全属性被破坏 | `远程启动/关闭信号的机密性遭到破坏` |
| **攻击行为/破坏方式** | 描述具体的攻击手段或破坏方式 | `可获取 TBOX 与 VCU 之间的远程控制指令交互规律` |
| **具体影响后果** | 说明对车辆功能、用户安全、财产、隐私的具体后果 | `掌握车辆远程上下电触发时机` |

### 编写要点

1. **一个损害场景只描述一个安全属性**被破坏的情况，不要混合多个属性
2. **描述要具体、可感知**，避免笼统表述如"造成影响"、"产生危害"
3. **同一个资产+安全属性组合可编写多个损害场景**，从不同攻击角度或不同后果维度描述（通常 2 个）
4. **区分行驶场景和驻车场景**：同一攻击在不同车辆状态下后果不同，应分开描述
5. **描述语言应精炼**，一句话完整表达三要素，一般不超过 80 字

### 编写示例（按安全属性分类）

#### 保密性 Confidentiality 损害场景示例

| 编号 | 损害场景描述 | 解析 |
|------|-------------|------|
| CsDS_AS_Da_001 | 远程启动/关闭信号的机密性遭到破坏，可获取 TBOX 与 VCU 之间的远程控制指令交互规律，掌握车辆远程上下电触发时机。 | 数据流被窃听→指令规律泄露→可预测车辆行为 |
| CsDS_AS_Da_002 | 远程启动/关闭信号的机密性遭到破坏，可解析远程控制通信格式，获取 TBOX 与 VCU 的指令交互特征。 | 更深层的协议分析→通信格式暴露 |
| CsDS_AS_Da_012 | 系统运行状态信号（HVAC/EAS→VCU）的机密性遭到破坏，可获取空调/加热系统运行状态与故障信息，掌握车辆能耗与使用习惯。 | 状态数据泄露→用户行为模式暴露 |
| CsDS_AS_Da_023 | 门锁状态信号的机密性遭到破坏，可长期监听 BCM→TBOX→云端通信链路，非法获取车辆锁止/解锁/设防/解防时序规律与停放安防信息。 | 安防状态泄露→车辆停放安全信息暴露 |

#### 完整性 Integrity 损害场景示例

| 编号 | 损害场景描述 | 解析 |
|------|-------------|------|
| CsDS_AS_Da_003 | 远程启动/关闭信号的完整性遭到破坏，TBOX 向 VCU 转发的指令被篡改，导致 VIU 内远程启动/关闭逻辑异常。 | 指令篡改→核心控制逻辑异常 |
| CsDS_AS_Da_008 | 高压/空调/加热唤醒/关闭信号（VCU→HVAC/EAS）的完整性遭到破坏，行驶中被篡改导致空调/除雾功能异常启停，干扰驾驶员正常操作。 | 行驶中篡改→安全相关功能异常→影响驾驶 |
| CsDS_AS_Da_019 | 远程闭锁/解锁信号（APP/TSP→TBOX→BCM）的完整性遭到破坏，行驶中信号被篡改导致车门异常解锁，引发行车安全隐患。 | 行驶中篡改→车门异常→直接安全威胁 |
| CsDS_AS_Da_020 | 远程闭锁/解锁信号（APP/TSP→TBOX→BCM）的完整性遭到破坏，驻车时恶意篡改解锁指令，造成车辆非法开启、财物被盗风险。 | 驻车时篡改→非法进入→财产损失风险 |

#### 可用性 Availability 损害场景示例

| 编号 | 损害场景描述 | 解析 |
|------|-------------|------|
| CsDS_AS_Da_005 | 远程启动/关闭信号的可用性遭到破坏，TBOX 无法正常接收并转发指令，导致 VIU 远程控制功能失效。 | 信号中断→远程控车功能失效 |
| CsDS_AS_Da_010 | 高压/空调/加热唤醒/关闭信号（VCU→HVAC/EAS）的可用性遭到破坏，行驶中无法正常唤醒空调除雾功能，影响驾驶员前方视野。 | 行驶中功能失效→安全视野受影响 |
| CsDS_AS_Da_011 | 高压/空调/加热唤醒/关闭信号（VCU→HVAC/EAS）的可用性遭到破坏，驻车时无法远程预热/预冷，车内舒适性功能失效。 | 驻车时功能失效→舒适性影响 |
| CsDS_AS_Da_021 | 远程闭锁/解锁信号（APP/TSP→TBOX→BCM）的可用性遭到破坏，行驶中无法正常下发闭锁指令，车门锁止失效存在安全隐患。 | 行驶中无法闭锁→行车安全隐患 |

## 影响分析评分算法

### 评分维度

影响分析从以下四个维度进行评分，每个维度独立评定，最终加权求和得出综合影响等级：

| 维度 | 英文 | 代码 | 含义 |
|------|------|------|------|
| 安全性 | Safety | S | 损害场景对人员（驾驶员、乘客、道路交通参与者）造成人身伤害的程度 |
| 财产 | Financial | F | 损害场景对组织/用户造成财产损失、维修成本、经营影响的程度 |
| 操作 | Operational | O | 损害场景对车辆功能、性能、可操作性的影响程度 |
| 隐私 | Privacy | P | 损害场景对用户/道路交通参与者个人隐私数据的影响程度 |

### 评分标准

#### 安全性 S（Safety）评分

| 分值 | 等级 | 判定标准 |
|------|------|---------|
| **0** | 无伤害 | 不会造成人员人身伤害风险。仅涉及数据读取、监听、采集等被动行为，无硬件操控、无安全功能干预。 |
| **10** | 轻度/中度伤害 | 可造成轻度至中度的人员伤害。涉及安全功能降级、异常操控信号、故障屏蔽导致隐患积累等。 |
| **100** | 严重/威胁生命伤害 | 可导致严重或威胁生命的人员伤害。涉及被动安全系统完全失效、高压危险失控、行驶中核心功能崩溃等。 |

**评分判断逻辑：**
- 仅涉及数据窃取、监听、日志查阅等纯信息类操作 → **S=0**
- 涉及信号篡改、指令伪造、功能屏蔽，可能间接引发安全隐患 → **S=10**
- 涉及安全气囊、高压系统、制动/转向等核心安全功能完全失控 → **S=100**

**S=0 典型评分理由示例：**
- "仅被动采集信号，不会造成任何人员人身伤害，符合 S0 无伤害标准"
- "仅监听 CAN 报文数据，无硬件干预与安全破坏行为，无安全隐患"
- "仅后台日志查阅统计，无硬件操作与功能改动，不存在人员伤害风险"

**S=10 典型评分理由示例：**
- "伪造安全带合规信号，弱化行车安全提醒，可造成轻度至中度安全影响"
- "篡改互锁信号屏蔽高压断开预警，遗留触电隐患，存在轻度至中度伤害风险"
- "屏蔽故障反馈延误检修，产生轻度安全隐患，符合 S1 轻度/中度伤害标准"

#### 财产 F（Financial）评分

| 分值 | 等级 | 判定标准 |
|------|------|---------|
| **0** | 无明显影响 | 微不足道的财产损失，未对受影响用户造成明显影响。仅涉及数据监听、日志查阅等，无硬件损耗、无部件老化、无维修成本。 |
| **1-10** | 可接受范围 | 造成可接受范围内的财务损失。涉及部件轻微老化、维修排查成本增加、低频次异常损耗等。 |
| **100** | 重大财务损失 | 所造成的损失会导致重大的财务损失，但不会威胁到组织的生存。涉及核心部件损坏、大规模维修更换、被盗风险、整车召回等。 |
| **1000** | 灾难性财务损失 | 所造成的损失会威胁到组织的生存（极少使用，一般保留给极端场景）。 |

**F 评分典型值分布：**
- F=0：纯信息操作，无硬件损耗
- F=1：轻微老化损耗，损失可忽略
- F=5-10：可接受范围内的维修成本、部件加速老化
- F=100：重大损失，核心部件损坏、被盗风险、大规模售后

**F=0 典型评分理由示例：**
- "仅被动监听数据，无硬件干预与零部件损耗，不产生维修成本，符合 F0 无明显影响标准"
- "日志查阅为软件访问行为，不会损伤电控零部件，无任何车辆财产损失"

**F=10 典型评分理由示例：**
- "信号不稳定加速线束老化，产生轻微损耗，损失程度可接受，符合 F1 可接受损失范围"
- "异常报文持续冲击控制器，造成模块轻微老化损耗，维修成本可控"

**F=100 典型评分理由示例：**
- "所造成的损失会导致重大的财务损失，但不会威胁到组织的生存"
- "车辆长期不设防，被盗风险升高，潜在大额财产损失风险"

#### 操作 O（Operational）评分

| 分值 | 等级 | 判定标准 |
|------|------|---------|
| **0** | 无明显影响 | 对车辆功能没有损坏或者是造成无法感知的损坏。仅涉及数据监听/读取，不改动车辆控制逻辑。 |
| **1** | 功能/性能降级 | 导致车辆功能的部分退化（非核心功能异常，影响驾驶体验和舒适度）。性能小幅下降、响应延迟等。 |
| **3-10** | 部分功能失效 | 导致车辆部分功能失效。非核心功能无法使用、远程服务失效、故障无法上报等。 |
| **100** | 非预期操作/无法工作 | 导致车辆发生非预期操作或无法操作、甚至无法工作。涉及核心控制功能完全失控、安全功能瘫痪。 |

**O 评分典型值分布：**
- O=0：仅数据监听/读取，不改动任何功能
- O=1：功能部分退化，性能降级（如响应延迟、状态刷新卡顿）
- O=3-10：部分功能失效（如远程空调失效、寻车功能失效、状态监测失效）
- O=100：核心功能完全失控（如全车电控紊乱、安防系统瘫痪、非预期行驶行为）

**O=0 典型评分理由示例：**
- "仅 CAN 报文监听采集，未改动车辆功能，无明显操作影响，符合 O0 无明显影响标准"
- "仅被动读取数据，未修改运行配置，不改动原车控制逻辑"

**O=1 典型评分理由示例：**
- "导致车辆功能的部分退化（非核心功能异常，影响驾驶体验和舒适度），符合 O1 性能降级标准"
- "通讯不稳定导致诊断使用体验与性能下降，符合 O1 功能性能降级标准"

**O=10 典型评分理由示例：**
- "导致车辆部分功能失效（远程寻车），远程服务闭环失效"
- "导致车辆部分功能失效（状态反馈），APP 与车端状态不一致"

**O=100 典型评分理由示例：**
- "导致车辆发生非预期操作或无法操作、甚至无法工作"
- "切断安全通信链路，整车被动安全联动控制完全离线"
- "伪造行驶信号，整车底层控制逻辑紊乱，运行秩序异常"

#### 隐私 P（Privacy）评分

| 分值 | 等级 | 判定标准 |
|------|------|---------|
| **0** | 无明显影响 | 隐私损害不会导致影响、影响的后果可忽略不计或者影响与道路交通参与者无关。不涉及个人隐私数据泄露。 |
| **10** | 轻微影响 | 隐私损害影响可忽略不计。涉及少量非敏感数据泄露（如车辆运行状态、VIN 信息等），不涉及可直接识别个人身份的信息。 |
| **100** | 严重影响 | 隐私损害导致严重影响。涉及大量个人身份信息泄露、用户行为轨迹暴露、位置隐私被持续追踪等。 |

**P=0 典型评分理由示例：**
- "隐私损害不会导致影响、影响的后果可忽略不计或者影响与道路交通参与者无关"
- "仅涉及车辆技术数据，不涉及个人隐私信息"

**P=10 典型评分理由示例：**
- "隐私损害不会导致影响、影响的后果可忽略不影响道路交通参与者"
- "可获取车辆使用习惯与能耗信息，但未涉及直接个人身份信息"

**P=100 典型评分理由示例：**
- "可获取车辆位置信息与用户出行轨迹，涉及隐私严重影响"
- "隐私损害导致大量用户个人数据泄露，造成严重影响"

### 综合影响等级计算

#### 计算公式

```
Total = S + F + O + P
```

#### 影响等级映射

| Total 范围 | 影响等级 | 英文 | 含义 |
|-----------|---------|------|------|
| Total ≤ 20 | 轻微 Minor | Minor | 影响几乎不存在或可忽略 |
| 20 < Total ≤ 100 | 中等 Moderate | Moderate | 造成一定影响，但在可接受范围内 |
| 100 < Total ≤ 1000 | 主要 Major | Major | 造成较大影响，需要重点关注和处理 |
| Total > 1000 | 严重 Severe | Severe | 造成严重影响，必须优先消除风险 |

#### 计算示例

**示例 1：保密性监控场景（低影响）**
```
CsDS_AS_Da_001: 远程启动/关闭信号的机密性遭到破坏
S=0（仅监听，无伤害）
F=100（指令规律泄露可能导致重大财务损失）
O=0（对车辆功能无影响）
P=10（涉及使用习惯隐私）
Total = 0 + 100 + 0 + 10 = 110 → 影响等级：主要 Major
```

**示例 2：完整性攻击场景（中高影响）**
```
CsDS_AS_Da_003: 远程启动/关闭信号的完整性遭到破坏
S=10（指令篡改导致逻辑异常，轻度伤害）
F=10（微不足道的财产损失）
O=100（导致车辆非预期操作）
P=0（无隐私影响）
Total = 10 + 10 + 100 + 0 = 120 → 影响等级：主要 Major
```

**示例 3：可用性破坏场景（中影响）**
```
CsDS_AS_Da_005: 远程启动/关闭信号的可用性遭到破坏
S=0（功能失效无直接伤害）
F=100（功能失效造成重大财务损失）
O=10（部分功能失效）
P=10（轻微隐私影响）
Total = 0 + 100 + 10 + 10 = 120 → 影响等级：主要 Major
```

**示例 4：纯信息采集场景（低影响）**
```
CsDS_AS_Da_007: 高压/空调/加热信号的机密性遭到破坏
S=0（仅采集，无伤害）
F=0（无硬件损耗）
O=0（无功能影响）
P=0（无隐私影响）
Total = 0 + 0 + 0 + 0 = 0 → 影响等级：轻微 Minor
```

**示例 5：行驶安全攻击场景（高影响）**
```
CsDS_AS_Da_008: 高压/空调/加热信号的完整性遭到破坏（行驶中）
S=10（干扰驾驶员正常操作，轻度伤害）
F=10（轻微财产损失）
O=1（功能部分退化）
P=0（无隐私影响）
Total = 10 + 10 + 1 + 0 = 21 → 影响等级：中等 Moderate
```

### 评分流程

1. **确定资产和安全属性**：明确当前评估的资产是什么、其哪个安全属性被破坏
2. **编写损害场景描述**：按照三要素公式，具体描述损害的发生方式和后果
3. **逐维度评分**：分别从 S/F/O/P 四个维度进行独立评分
4. **撰写评分理由**：每个维度的评分都需要给出具体理由，参考上述各维度「典型评分理由示例」
5. **计算 Total**：将四个维度分值相加
6. **判定影响等级**：根据 Total 值查表确定 Minor / Moderate / Major / Severe

### 评分注意事项

1. **每个评分必须附带评分理由**，理由应具体说明为什么给出该分值，而非简单重复等级描述
2. **同一资产的不同安全属性**通常对应不同的评分分布（如保密性→S 低+F 可能高，完整性→S 高+F 低）
3. **区分行驶/驻车场景**：同一攻击在不同场景下后果不同，评分也应不同（行驶中通常 S 更高）
4. **隐私 P 维度**在大多数技术类资产场景中为 0 或 10，仅在涉及用户个人数据时才有较高评分
5. **安全性 S 维度**一般只有 0、10、100 三个档位，不存在中间值
6. **操作 O 维度**需要有层次地区分"降级"(O=1)、"部分失效"(O=1-10)和"完全失控"(O=100)
